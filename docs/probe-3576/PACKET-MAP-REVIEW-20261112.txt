What remains unproved
Names and IDs do not establish payload field offsets or cross-PC identity.
The partial handler walks do not prove complete Req/Ack layouts, cursor
consumption on every successful path, or that all packet sizes are fixed.
The 16-byte samples cannot establish complete transforms or replayable data.
The map appropriately marks these limits. The proposed collector is still
unimplemented and has not been validated by this review.

Next Grok task: implement the proposed bounded collector, with these details
1. Keep the nine-message selection in experimental 3576 code only. Filter
   before expensive copying, using a guarded opcode read when length >= 2.
   For selected ordinary messages, require at least five claimed bytes,
   read the guarded five-byte header, and validate header_payload_length+5
   against the stack length. Unselected internal three-byte messages are
   filtered, not mislabeled as malformed ordinary frames. Distinguish
   filtered-out, malformed, unreadable,
   truncated, queue-dropped, and output-omitted records/counters.
2. Preserve claimed length and copied length separately. Use a 4096-byte
   copy cap and a wide enough length field. A record is complete only if
   its frame is consistent and the entire claimed packet was copied.
   Failed/partial reads must not expose uninitialized bytes or be labeled
   complete. A truncated 4096-byte actor-load sample is not a usable spawn
   packet. Its unknown maximum must stay explicit, not silently increased.
3. Preallocate the queue/output storage. A 256-slot ring plus 256 retained
   records with 4096-byte arrays costs roughly 2 MiB before overhead; check
   the actual sizes. Keep callback copying bounded with no allocation, file
   I/O, blocking lock, or retained pointers into game buffers. Size the writer
   for 8192 hex characters plus metadata, or use another bounded encoding.
4. Add per-record QPC ticks and session QueryPerformanceFrequency metadata.
   Use separate labeled stand/walk/turn arm-stop windows with archived files,
   or marks using a documented matching time base. Preserve the first-bound
   directory rule and fixed-file overwrite precautions. Keep the record cap
   explicit; 256 does not guarantee a whole action interval is captured.
5. Preserve admission/drain/quiescence and Retained ownership. Keep both
   loaded-file/signature guards, production/fixture separation, and stop
   behavior. Do not open the normal ASI guard or add packet sending/replay.
6. Add meaningful game-free tests for selected and unselected opcodes,
   malformed/short frames, unreadable/page-boundary buffers, exact-cap and
   over-cap packets, complete/truncated flags, QPC metadata/phase labeling,
   queue/output limits and counters, packet immutability, concurrent stop,
   and retained failures. Run the existing suite and appropriate sanitizer
   checks, then return for Codex review before requesting another live run.
