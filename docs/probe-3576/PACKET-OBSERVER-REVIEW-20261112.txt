Resolved findings

  delete an observer if hook removal fails. Retained object behavior is tested.

Remaining P1 finding: admission is not synchronized with retirement
tools/pkt3576/observer.cpp, consumer_enter lines 135-142 and retire_queue
lines 151-155; producer_enter lines 123-130 uses the same pattern.

open_ and the inflight counters are separate atomics. A release store closing
open_ followed by acquire loads of the counters is not an atomic close-and-drain
operation. Retirement can observe zero while a concurrent entrant increments
its counter and still sees open_ == true. The queue can then be freed while
that entrant is admitted. The reduced test uses the same initial open load,
counter fetch_add(acq_rel), second open load(acquire), and retirement's release
store followed by acquire counter loads. It reproduces on this x64 machine.

The new consumer-hold test pauses after consumer_enter has registered the pop,
so it checks draining a known reader but misses this admission race.

Requested fix
Use a proven admission/retirement protocol, such as a single atomic state with
a closed bit and active count, so acquiring admission and closing admission
have one defined order. Cover both producers and the consumer. Add coverage
for racing admission with shutdown, not only a pause inside an admitted pop.
Keep callback operations nonblocking and keep the existing identity, bounded
read, failed-removal, and capacity checks. State the owner/thread lifetime
requirements before release_owner can delete an object. Re-run the suite.
