P1: Active capture prevents production status and stop
File: tools/pkt3576/live_control.cpp, lines 567-575.
execute() applies identify_image() and modification_allowed() to every command
before finding or calling the already-loaded diagnostic module. identify_image
requires the pristine 16-byte send and receive entries. Capture::start installs
SafetyHook patches at exactly those entries, so a successful production start
makes the next status or stop reject with signature-mismatch / exit 4. The
operator cannot inspect or stop that capture through the advertised commands;
hooks and the writer remain active. The fixture controller flow misses this
because its fixture gate accepts a non-game executable without those signatures.

Independent reproduction: build/review_live_controller.cpp uses synthetic PE
headers with the documented identity and real SafetyHook mid hooks on private
executable pages containing the candidate entry bytes. No process is opened.
Output:
before=match active=signature-mismatch production_status_stop_allowed=0 after=match

Required correction: separate immutable executable identity from the pristine
entry check required before a new arm. Preserve the full version/signature gate
for loading/arming. Provide a validated way to query and stop the existing
approved module while its own hooks are installed. Do not broadly accept a
signature mismatch or introduce a force flag. Add game-free regression coverage
that exercises production control policy with patched entries; fixture-only
start/status/stop success does not cover this case. Wrong name/build/base/size,
including 2976, must still be rejected without modification.

P2: PID parser accepts overflow as another PID
File: tools/pkt3576/live_control.cpp, lines 136-139.
Windows unsigned long is 32 bits. The check tests value > UINT32_MAX/10 before
multiplying, but omits the final-digit limit when value equals that quotient.
Values above 4294967295 can wrap before the later range check. The controller
then opens the wrapped PID rather than rejecting the supplied PID as usage.
Independent reproduction calls the actual parser in the same translation unit:
overflow_pid_accepted=1 resulting_pid=1
Input was 4294967297. No OpenProcess call is made by this reproduction.

Required correction: reject when value > (UINT32_MAX - digit)/10 before
accumulating, or use an equally strict checked conversion. Add boundary tests
for 0, UINT32_MAX, UINT32_MAX+1 through +9, huge decimal strings, and ordinary
valid PIDs. Invalid inputs must return usage without opening a process.
