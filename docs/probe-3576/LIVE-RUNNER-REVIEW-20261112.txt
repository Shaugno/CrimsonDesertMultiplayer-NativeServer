P1: stop exceptions reopen Idle while hooks remain installed
File: tools/pkt3576/live_runner.cpp, lines 424-435, plus Slot's default phase.

Capture::stop is not noexcept. SafetyHook's disable path can allocate while
adding a trap to its std::map. An exception from g_capture->stop has no handler
in live::stop or the C export. During unwinding, Slot defaults to kPhaseIdle.
The hook can remain patched, but another stop immediately returns Idle and
status still says retained=0. This loses the runner's active/retained lifecycle
state and can let a later start overwrite the pointer to a still-live capture.

Reproduction uses one injected std::bad_alloc on the next allocation after
fixture startup succeeds. Observed with a 96-byte allocation:
stop_exception_escaped=1 allocation_size=96 receive_still_patched=1 next_stop=5 retained=0
Here next_stop=5 means Idle. The child exits 94 as a failure verdict.

Requested fix: contain teardown exceptions at the runner/C-ABI boundary. Keep
Held/Retained state, the capture owner, writer, and module pin whenever cleanup
cannot be proved complete. Do not reset Idle with installed hooks. Ensure the
exception paths of release_capture are contained too. Add regression coverage
for allocation failure during backend stop and for truthful follow-up status.

P2: a failed initial log binding blocks a valid destination
File: tools/pkt3576/live_runner.cpp, lines 245-253.

CreateDirectory's ERROR_ALREADY_EXISTS is accepted without checking that the
existing object is a directory. More generally, g_log_bound and both path
globals are committed before log_flush succeeds. If the initial log cannot
be opened, start returns BadLog but keeps that failed binding. A retry with
a different valid absolute directory is then rejected by the bound-dir check,
even though no capture has been attempted and no session was established.

Reproduction supplies a temporary regular file as the first directory, then
a fresh valid absolute directory. Observed:
bad_path_code=6 retry_good_path_code=6 capture_attempts=0
Both calls return BadLog; the second should be able to start the fixture.
The child exits 95 as a failure verdict.

Requested fix: validate existing destinations as directories and commit the
initial binding only after the session log is successfully opened/written.
Roll back failed initial binding state. Test a regular-file destination and
a session-file open failure followed by a successful start in a good folder.
