# cdmp_diag3576

External read-only position diagnostic for Crimson Desert 1.0.0.3576. It reuses `probe::Process` (`PROCESS_VM_READ | PROCESS_QUERY_INFORMATION`). It does not inject, hook, write process memory, open a socket, or install `cdmp.asi`. It does not include `offsets.h` or `build_guard.h`.

The ASI compatibility guard stays closed. The mod still accepts only build 1.0.0.2976. This tool's acceptance of timestamp `0x6AED2E85` does not mark 3576 supported.

Experimental addresses live in `tools/diag3576/candidates.h`. They are not production offsets.

## What a sample is

The operator passes `--pid` and `--slot exe+0xRVA`. There is no attach by process name and no default slot. `exe+0x71C09A8` is only the temporary sampler from the 2026-11-12 session. It is not a permanent root.

Identity required by this tool:

- Module basename `CrimsonDesert.exe`.
- Mapped base `0x140000000`.
- PE timestamp `0x6AED2E85`.
- The origin and static candidates lie inside the module.

Timestamp `0x6AB28F00` (1.0.0.2976) is rejected. A rejected identity exits 2 and prints that the mod guard was not opened.

The slot must be a nonzero 8-byte-aligned RVA inside the module. The banner labels it as an experimental candidate. The chain is manager-rooted. `+0x30` is not applied. Every sample resolves it again:

`slot -> +0x50 actor -> +0x68 component table -> +0x40 character -> +0x140 inner -> +0x2C0 physics -> +0x90 local`

Required RTTI, exact names:

- `ClientActorManager`
- `ClientChildOnlyInGameActor`
- `ClientCharacterControlActorComponent`

A null pointer on those hops is `chain-invalid`. It is not a loading detector. Loading detection is unresolved.

Origin candidate `exe+0x71AC2C0` and static candidate `exe+0x71CF140` are read and labeled not adopted. World position is `local + origin`, using the origin read taken before the chain. Residual is `static - world` on X, Y, Z, and W. Y is measured and not corrected. A large residual can still be `coherent`.

Each attempt reads the origin and the pointer identities, then reads them again after the position values. A changed origin, a replaced pointer, an unreadable value, or a non-finite value is retried up to 3 times and then flagged. Process exit is not retried. The process prints one line per requested sample.

`status=coherent` means that attempt's reads were stable, readable, and finite. It does not mean the player is ready or in the world. Every sample line includes `player-ready=unresolved` and `loading=unresolved`.

## Build

From the NativeServer repo:

```powershell
powershell -NoProfile -File scripts\build.ps1
```

The executable is `build\bin\RelWithDebInfo\cdmp_diag3576.exe`. The focused test is `diag3576`.

## Usage

Start the game from the Steam library. Do not run `scripts\launch-2inst.ps1`. Do not copy `cdmp.asi` into the game.

```powershell
build\bin\RelWithDebInfo\cdmp_diag3576.exe --pid PID --slot exe+0x71C09A8 --count 1
```

A longer log, one sample per second:

```powershell
build\bin\RelWithDebInfo\cdmp_diag3576.exe --pid PID --slot exe+0x71C09A8 --count 30 --interval 1000
```

`--count` is 1 through 1000. `--interval` is 0 through 60000 milliseconds. Missing arguments, a bad slot, or a rejected identity exit 2. If the process exits during sampling, the tool prints `status=process-exited` and returns 0.

Stdout is the log. Redirect it to keep a file. Each line has the local timestamp, status, attempt count, local, origin, world, static, residual, and the pointer identities (`manager`, `actor`, `component-table`, `character`, `inner`, `physics`, `local-field`). An origin that changed during the sample adds `origin-after`. A retry that then succeeded adds `recovered-from`.

## Status values

| Status | Meaning |
| --- | --- |
| `coherent` | Origin and pointer identities matched before and after. Every value was readable and finite. Y is left as measured. |
| `origin-changed` | The origin candidate differed across the sample after the retries. |
| `pointers-changed` | A chain pointer differed across the sample after the retries. |
| `unreadable` | A required read failed while the process was still alive. |
| `non-finite` | A component was NaN or infinite. |
| `chain-invalid` | A required pointer was null or the RTTI did not match. Not a loading signal. |
| `process-exited` | The process ended. Not retried. |

## Tests

`ctest --test-dir build -C RelWithDebInfo -R diag3576 --output-on-failure` covers:

- Coordinate addition, with residual Y left at `-0.25` and not replaced by zero.
- A large static residual staying `coherent`.
- An origin change that settles on the next attempt, then an origin that changes on every read.
- A manager pointer replaced between the before and after chain.
- An unreadable static candidate and a NaN local.
- Rejection of timestamp `0x6AB28F00`, a wrong image base, and an unaligned slot.
- Process exit before a sample and during the local-position read.

The tests use fake memory. They do not launch the game.

## Live validation checklist

For a later session. This patch does not launch the game.

1. Start Crimson Desert 1.0.0.3576 from the Steam library. Do not run `scripts\launch-2inst.ps1`. Do not copy `cdmp.asi`.
2. Pass that process's PID and an explicit manager-rooted slot. The header must show timestamp `0x6AED2E85`, base `0x140000000`, the experimental slot, the closed-guard line, and the unresolved loading line.
3. A wrong PID fails at open and prints no sample. The 2976 timestamp is rejected before samples; the unit test covers `0x6AB28F00` when that executable is not running.
4. With the character standing still, `--count 1` should print `status=coherent`, a residual whose Y was not forced to zero, and `player-ready=unresolved`. Coherent is not "in world."
5. Walk, stop, and run `--count 1` again. The chain is resolved again. Local should differ from the standing sample, or the line should flag an origin or pointer change. Y is still not corrected.
6. Run `--count 5 --interval 500` and close the game during the run. The tool should print `status=process-exited` and return normally.
7. After the run, `src/mod/game/offsets.h` and `src/mod/game/build_guard.h` must be unchanged. Do not adopt `exe+0x71AC2C0`, `exe+0x71CF140`, or the slot. Do not reuse heap addresses from an earlier PID. A null actor is `chain-invalid` and is not a loading signal.
