P1: mark can use a Capture after stop deletes it
 tools/pkt3576/live_runner.cpp:661-678, especially line 666.
mark() reads g_capture and invokes set_phase() without participating in the
start/stop ownership synchronization. stop() can concurrently remove hooks and
release_owner() can delete the Capture. The pointer check does not protect the
subsequent call. New mark logging/state mutations and non-atomic report fields
also need a shared synchronization policy with lifecycle operations.

Independent reproduction: actual runner and backend code, dummy hook targets,
with one review-only scheduling pause inserted at Capture::set_phase entry.
Pause mark there, execute the real stop/release, then resume mark:
 fixture_start=0
 mark_suspended=1 stop_result=4 capture_deleted_while_mark_inflight=1
 AddressSanitizer: heap-use-after-free
ASan reports the freed Capture access from live::mark, with the freeing stack
through Capture::release_owner -> release_capture -> live::stop.

Required fix: coordinate all mark access to the owner and mutable phase/log
state with start/stop/release; provide race-free report snapshots. Synchronize
control threads without putting blocking locks in packet callbacks. Retained
must keep its ownership guarantees. Add a deterministic mark/stop regression
that proves the owner cannot be freed while a phase operation uses it, and
stress overlapping control/report calls. A zero active-hook callback count
alone does not account for the new mark control thread.

P2: complete status describes an earlier header, not the copied packet
 tools/pkt3576/observer.cpp:277-290.
observe() separately reads the opcode, reads/validates a five-byte header, and
then copies the frame. Complete/truncated status and metadata use the earlier
reads; the copied bytes are never revalidated. A changing buffer can therefore
produce a complete record whose own header has a different opcode or length.

Independent synthetic ReadFn reproductions, each with claimed/copied=8:
 length-changed: status=1 (Complete), metadata payload=3, copied payload=65535.
 opcode-changed: status=1, metadata opcode=3094, copied opcode=4660 (0x1234).
Both used exactly three reads of the packet address. No game memory was used.

Required fix: validate the actual copied header and maintain agreement between
its opcode/length and the record metadata/claim before declaring Complete or
Truncated. Reject or explicitly classify inconsistent snapshots; an unselected
opcode must not appear as a complete selected message. Do not claim an atomic
snapshot of the entire game payload merely because header checks pass. Add
reader-mutation regressions for both header and opcode changes, alongside the
existing short, malformed, unreadable, cap, and partial-read cases.

P2: phase-file preservation is a check-then-overwrite race
 tools/pkt3576/capture.cpp:718-720; runner precheck at live_runner.cpp:453-461.
The runner checks file_exists(), but the backend later opens the path with
_wfopen_s(..., L"wb"), which truncates an existing file. A phase archive created
between those operations is overwritten despite the no-overwrite contract.

Independent reproduction: a review-only scheduling point immediately before
the records open creates the phase file with a known previous-capture marker,
after the real runner precheck has succeeded. Then actual start/stop run:
 phase_file_created_after_precheck=1 start_result=0 stop_result=4 prior_archive_preserved=0

Required fix: atomically create labeled phase files exclusively and refuse an
existing destination. Keep overwrite behavior only for the explicitly unlabeled
path. Add a regression that creates the destination between preflight and open
and verifies unchanged original bytes plus refused/rolled-back startup with no
live hooks. Do not rely on another existence check to close this race.
