P1: a vanished thread can make enumeration loop forever
File: tools/pkt3576/capture.cpp, lines 189-198.
When OpenThread returns null with ERROR_INVALID_PARAMETER, continue skips
the Thread32Next call at the bottom of the loop. The same snapshot entry is
processed again indefinitely. This can occur naturally if a thread exits
after the snapshot. The outer quiesce deadline cannot interrupt this loop,
so stop/rollback can hang rather than return Removed or Retained.

Reproduction: review_capture_dead_thread.cpp includes the actual capture.cpp
and substitutes OpenThread with a shim returning ERROR_INVALID_PARAMETER
for one enumerated worker. The second attempt to open that same id reports
the loop and terminates the test child with exit 91 (a watchdog verdict).
Observed: FAIL: the same vanished-thread entry was retried instead of
advancing; attempts=2

Requested fix: ensure every skipped dead entry advances enumeration. Check
enumeration errors distinctly from normal completion and fail closed when
the scan cannot be completed. Add deterministic coverage for disappearing
threads and scan errors; verify handles and suspended threads are cleaned up.

P2: allocation failure leaves global capture ownership stuck
File: tools/pkt3576/capture.cpp, lines 562-576.
start claims g_active and may open/truncate the output file before
records.reserve. reserve can throw, but this operation has no rollback.
After the caller catches the exception and releases the failed Capture,
g_active still references its deleted State. A fresh Capture then fails the
global ownership CAS and returns Refused. Capture cannot recover in-process.

Reproduction: review_capture_allocation.cpp links the real capture backend
and injects std::bad_alloc for the records.reserve allocation (including the
MSVC aligned-allocation overhead). No huge allocation is requested.
Observed: injected reserve failure escaped=1; subsequent fresh start refused=1
Exit 92 denotes reproduction of both symptoms.

Requested fix: allocate fallible storage before claiming global ownership,
or add a transactional cleanup guard that resets g_active and closes the file
on all pre-hook failures/exceptions. Return Refused for expected allocation
failure. Add an injected-failure test proving that a subsequent start works.
