Reviewed behavior
- Production start identifies the loaded process executable and requires the
  documented CrimsonDesert.exe name, mapped base, timestamp, image size, and
  both candidate entry signatures before Capture::start.
- Unsupported/unreadable identities and build 2976 are rejected. The production
  DLL has no fixture export; fixture authorization remains a separate test build.
- DllMain performs no capture, log, or worker startup. Explicit arming pins the
  diagnostic module before exposing callbacks. The pin lasts until process exit.
- Stop/release exceptions preserve Held/Retained ownership and truthful status.
  A later start cannot overwrite that capture; no cleanup is retried as Idle.
- Failed initial log binding restores its previous state. Existing files are
  rejected as directories, and a failed session-file open permits a good retry.
- Production ASI guard/offsets are unchanged. No process launcher or remote
  injector is included, and the diagnostic module is not linked into cdmp.asi.

Limits and next task
All validation used dummy functions, fake identity data, and self-owned test
processes. No game was launched, attached, or modified. Fixture logs are marked
fixture=1/game_match=0 and do not establish game compatibility.

The module exports an in-process start/stop/status API. A real-game loading and
controller route is still to be selected, implemented, and reviewed. Keep that
separate from deployment. Future live tests require the user's instruction and
save backup under CLAUDE.md. Keep the normal ASI guard closed.

resources until process exit and is not a request to force-unload the DLL.
