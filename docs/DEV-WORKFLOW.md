# Local development: Visual Studio, Grok Build, and Codex

Project home: https://github.com/Shaugno/CrimsonDesertMultiplayer-NativeServer

Original source: https://github.com/ByJunter/CrimsonDesertMultiplayer-NativeServer

This NativeServer checkout is Shaugno's independent continuation. ByJunter's
upstream alpha targets game build 1.0.0.2976; this continuation is developing
compatibility for 1.0.0.3576. The production guard still accepts only 2976.
`origin` points to Shaugno and `upstream` retains the original repository.
The `shaugno` remote is also kept as a publishing alias. The original mod lives
in the sibling folder `CrimsonDesertMultiplayer` and must stay untouched. The
parent `COOP MOD\Start-Grok.ps1` still opens that original checkout; leave the
launcher alone unless the user asks to retarget it. Point Codex at this
NativeServer folder for reviews.

## Start working

1. In Visual Studio, choose **File > Open > Folder** and select this repository.
   It is a CMake C++20 project; no source .sln file is required.
2. Install **Desktop development with C++**, including MSVC x64, the Windows SDK,
   and C++ CMake tools. The .vsconfig records the workload.
3. In PowerShell at the repository root, run `.\scripts\build.ps1`.
   The script selects the Visual Studio 17 2022 generator or the Visual Studio 18
   2026 generator from the installed C++ toolset. CMake comes from that Visual
   Studio install. First configure downloads the dependencies pinned in
   CMakeLists.txt. After a successful configure, you can also open
   `build\CrimsonDesertMultiplayer.slnx` in Visual Studio 2026 (or the `.sln`
   generated by Visual Studio 2022).
4. Keep Codex pointed at this checkout for reviews. Both assistants can inspect
   the same local files; wait for implementation to finish before reviewing.

If an existing build directory was configured for a different generator, use a
separate build directory or move the old build aside before reconfiguring.

## Give Grok a task

> Investigate [issue link or symptoms]. Read AGENTS.md and CLAUDE.md.
> Reproduce the failure or identify the missing evidence, explain the likely
> cause with file references, and propose a focused fix. Implement the agreed
> task and run relevant validation. Finish with a handoff for Codex containing
> the diff summary, test results, runtime limitations, and reproduction steps.

## Ask Codex to review

> Review the changes in CrimsonDesertMultiplayer-NativeServer. Check correctness,
> regression risks, network input validation, memory safety, and test coverage
> against the original issue. Give actionable findings with file and line
> references. Run relevant checks and distinguish verified behavior from
> remaining assumptions.

Give findings back to Grok, then request another review after fixes. Review is
requested explicitly; this setup does not automatically monitor Grok sessions.

## Before in-game tests

Follow CLAUDE.md and the game-version requirement. Compile and run unit tests
first. Back up saves before tests that write game memory or inject messages.
Use the repository's test tools (`cdmp_host`, `cdmp_peer`, `cdmp_dx12_test`)
before a two-PC test. Record the exact game build, mod commit, host/guest
roles, steps, and relevant log excerpt for any bug report. Do not deploy the
mod or launch Crimson Desert unless that task is requested.
